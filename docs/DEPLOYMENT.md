# Keys, secrets and deployment

How to run your own copy: create the accounts and keys, run it locally, deploy it to DigitalOcean App Platform, and
add a custom domain. No code changes are needed; the app reads every secret from environment variables.

| Where the app runs | Where the keys go |
|---|---|
| Your laptop | `.env` in the project root (git-ignored; start from `.env.example`) |
| DigitalOcean | App → Settings → each component → Environment Variables (tick "Encrypt") |

Never put keys into code, commits or issues. Operating the running system (ledger switches, monitoring, AWS, secret
rotation) is in [`RUNBOOK.md`](RUNBOOK.md).

---

## 1. Accounts and keys (about 30 minutes)

### 1.1 MongoDB Atlas → `MONGO_URL`
Users, Behavioral Mirror events, AI memory, analyses, watchlists and messages.
1. Sign up at <https://www.mongodb.com/cloud/atlas/register> and create an **M0 (Free)** cluster (AWS, any nearby region).
2. Create a database user (**Security → Database Access**) with an autogenerated password.
3. **Security → Network Access → Add IP Address → Allow Access from Anywhere** (`0.0.0.0/0`). DigitalOcean has no
   fixed outbound IP.
4. **Database → Clusters → Connect → Drivers**: copy the string, put the password in place of `<db_password>`, and add
   the database name after `.net/`:
   `mongodb+srv://<user>:<db_password>@<cluster-host>/niveshpath?retryWrites=true&w=majority`
   If the password contains `@ : / ? # %`, generate one without symbols; they break the URL.

The app creates its collections on first use.

### 1.2 PostgreSQL (Neon) → `DATABASE_URL`, `DIRECT_URL`
The money ledger (cash and trades; [`LEDGER.md`](LEDGER.md)).
1. Create a project at <https://neon.tech> (Postgres 18, region AWS US East).
2. **Connect** with pooling **on**: copy the URL and append `&pgbouncer=true` → `DATABASE_URL` (the app).
3. **Connect** with pooling **off** → `DIRECT_URL` (migrations only; they can't run through the pooler).
4. Set `LEDGER_BACKEND=postgres`. Without `DATABASE_URL` the app can run on the MongoDB ledger (`LEDGER_BACKEND=mongo`).

Locally, `docker compose up` starts a Postgres 18 for you.

### 1.3 Finnhub → `FINNHUB_API_KEY`
Sign up at <https://finnhub.io/register> (free plan) and copy the API key from the dashboard. The free plan allows 60
calls a minute; quotes are cached, so that's enough.

### 1.4 Anthropic → `ANTHROPIC_API_KEY`
The AI Advisor and coach use an LLM through the Anthropic Claude API. Create a key at <https://console.anthropic.com>
(**Settings → API Keys**) and add a few dollars of credit; each analysis costs a few cents. The model comes from
`CLAUDE_MODEL`. Without a key, the Advisor and coach still answer with rule-based analysis.

### 1.5 Generated secrets → `JWT_SECRET`, `AI_INTERNAL_TOKEN`
```
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"   # JWT_SECRET
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"   # AI_INTERNAL_TOKEN
```
`JWT_SECRET` signs login tokens; production refuses to start without it. `AI_INTERNAL_TOKEN` is shared by the web
and AI services: with it set, the AI service answers only the web service, and web's `/internal` API (read by the AI
service and the nightly job) exists only with it.

### 1.6 Optional
- **Sentry** (`SENTRY_DSN`): error tracking. Create a Node.js (Express) project and copy its DSN.
- **Resend** (`RESEND_API_KEY`, `CONTACT_TO_EMAIL`): email for the contact form.
- **Grafana Cloud** (`OTEL_*`): traces, metrics and logs ([`OBSERVABILITY.md`](OBSERVABILITY.md)).

### 1.7 `.env`
```
cp .env.example .env
```
Fill in the values above. Every variable is explained in `.env.example`.

### 1.8 Check it locally
```
docker compose up --build                 # everything: http://localhost:3000
```
or run the services yourself (README, "Run locally"). Then:
- <http://localhost:3000/health> shows `"status":"ok","db":"connected"`;
- <http://localhost:8001/health> shows `"llm_configured":true` when the Anthropic key is set;
- sign up, buy a share on any stock page: cash drops and the trade appears on Transactions;
- the Advisor's badge says **AI insight** (or "Rule-based insight" without a key).

## 2. Deploy to DigitalOcean App Platform (about 20 minutes)

1. <https://cloud.digitalocean.com/apps> → **Create App** → **GitHub** → **Manage Access**: authorize DigitalOcean for
   the repository. Select it, branch `main`, tick **Autodeploy**.
2. Replace the auto-detected component with the spec: **Edit App Spec** (or **Settings → App Spec → Edit**), paste
   [`.do/app.yaml`](../.do/app.yaml), save. You get services **web** (public) and **ai** (internal) and the
   **migrate** pre-deploy job.
3. **Secrets:** for each component, **Settings → (component) → Environment Variables → Edit**, paste the values and
   tick **Encrypt**:

   | Component | Variables |
   |---|---|
   | web | `MONGO_URL`, `DATABASE_URL`, `FINNHUB_API_KEY`, `JWT_SECRET`, `AI_INTERNAL_TOKEN`; optional `SENTRY_DSN`, `RESEND_API_KEY` + `CONTACT_TO_EMAIL`, `OTEL_EXPORTER_OTLP_HEADERS` |
   | ai | `ANTHROPIC_API_KEY`, `MONGO_URL` (same as web), `AI_INTERNAL_TOKEN` (same as web); optional `SENTRY_DSN`, `OTEL_EXPORTER_OTLP_HEADERS` |
   | migrate | `DATABASE_URL`, `DIRECT_URL` |

   Set `AI_INTERNAL_TOKEN` on ai and web in the same save (or web first). If only ai has it, the Advisor and coach
   stop answering until web has it too. `AI_SERVICE_URL`, `WEB_INTERNAL_URL`, `PUBLIC_BASE_URL`, `CLAUDE_MODEL` and
   `LEDGER_BACKEND` come from the spec.

   **Why ai needs `MONGO_URL`:** App Platform wipes the container disk on every deploy, so the AI service's ChromaDB
   index starts empty. On boot it rebuilds each user's index from their trades, and coach results are stored in
   MongoDB. Without it the Advisor still works but forgets past trades after each deploy.
4. **Deploy:** **Create Resources**. The first build takes 5–10 minutes (Activity tab). The `migrate` job log ends
   with `All migrations have been successfully applied.`
5. **Check:** `/health` shows `"status":"ok","db":"connected"`; What's new shows all systems working; the Advisor's
   badge says **AI insight**.

| Symptom | Fix |
|---|---|
| The ai build fails with "Dockerfile not found" | In the App Spec, `dockerfile_path` is relative to `source_dir`; check both |
| `/health` shows `"db":"disconnected"` | `MONGO_URL`, and Atlas Network Access (§1.1 step 3) |
| The deploy stops at the `migrate` job | `DATABASE_URL` / `DIRECT_URL` on the job; the running version stays up |
| More | [`RUNBOOK.md`](RUNBOOK.md) §1 |

**Cost:** web (0.5 GB) about $5/month and ai (1 GB) about $10/month. Destroying the app stops billing; it can be
recreated from the spec.

## 3. Custom domain (about 20 minutes)
1. Register a domain with any registrar.
2. DigitalOcean: the app → **Settings → Domains → Add Domain** → "You manage your domain". It shows a **CNAME target**
   (`<app>.ondigitalocean.app`).
3. At the registrar's DNS settings: a `CNAME` record for `www` pointing at that target; for the root (`@`), a
   CNAME/ALIAS record if the registrar allows one, otherwise a redirect from `@` to `https://www.<domain>`, or move
   DNS to DigitalOcean (Networking → Domains, nameservers `ns1/ns2/ns3.digitalocean.com`).
4. Wait 5–60 minutes. DigitalOcean issues the HTTPS certificate automatically (Let's Encrypt); the domain shows
   "Active". `PUBLIC_BASE_URL` follows it (`${APP_URL}`).
